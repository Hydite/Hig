# HIG Production Completion Design

## Goal

Move every HIG delivery track to evidence-backed completion without weakening
archive security, recovery exactness, atomic publication, performance, or IDE
filesystem confinement.

## Completion Model

Completion is a release property, not a source-code count. A track reaches
100% only when its implementation, failure behavior, automated regression
coverage, native-platform behavior, and distributable artifact are all proven.
Missing evidence counts as incomplete.

The five release tracks are:

1. repository history and revision references;
2. IDE automatic snapshot policy and recovery;
3. cold archive performance and no-regression gates;
4. native macOS, Linux, and Windows CLI/MCP packages;
5. archive, repository, cache, and protocol compatibility.

## Architecture

The existing HIGV2 archive format and content-addressed repository remain the
data sources of truth. This stage adds a versioned verification layer around
them:

- immutable synthetic golden fixtures produced by historical release binaries;
- current-reader extraction and migration gates;
- native operating-system build and MCP protocol matrices;
- deterministic snapshot fault, overflow, pressure, and soak scenarios;
- counterbalanced performance gates with exact restore digests;
- release provenance and checksums generated by the same CI run as binaries.

Runtime-generated archives are retained for implementation tests, but they do
not replace historical golden fixtures. Cross-compilation may diagnose target
issues, but native execution is required for a production package.

## Failure Policy

Every gate fails closed. A missing fixture, skipped historical reader, missing
native target, MCP tool-schema regression, checksum mismatch, partial restore,
or absent performance baseline fails the associated release track. CI may
report an environment as unqualified, but it may not report a product gate as
passed without the required evidence.

Archive and repository migrations continue to stage, verify, sync, and rename
before replacing a target. Compatibility helpers never modify immutable golden
fixtures. IDE snapshot pressure or watcher failure leaves state Dirty or
Invalid until recovery; it cannot publish a stale Ready snapshot.

## Platform Delivery

- macOS: universal arm64/x86_64 CLI plus Node MCP adapter.
- Linux: native x86_64 GNU CLI plus Node MCP adapter.
- Windows: native x86_64 MSVC CLI plus Node MCP adapter.

Each package runs CLI version, archive round-trip, repository exact restore,
MCP initialize/tools/list/tools/call, path-confinement, and checksum checks
after extraction.

## Performance Policy

Performance changes require same-corpus ABBA comparison, fresh HIG caches,
qualified storage metadata, stage telemetry, peak-memory comparison, archive
size comparison, and per-file restore digests. A candidate fails if it reduces
compression quality, increases peak memory beyond the declared budget, weakens
security, or regresses a protected median outside the declared noise margin.

## Public Boundary

All committed fixtures are synthetic and use public test-only passwords. No
private project, benchmark corpus, user path, cache state, credentials, paper
source, PDF, or research archive belongs in the completion suite.
