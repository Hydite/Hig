## 摘要

我们构建 Hig，是为了提供一个快速、紧凑、加密的项目归档桌面应用。目标是在实际开发过程中让项目快照变得足够轻：速度足够频繁运行，体积足够长期保留或迁移，同时保留必要的完整性校验。

在我们的最新公开基准测试中，Hig 与 `zip`、`tar.gz`、`tar.zst` 在同一测试语料上进行直接对比。结果显示，Hig 在生成更小归档体积的同时，显著降低了项目归档流程耗时。

## 核心优势

| 优势 | 最新公开对比结果 |
| --- | --- |
| 速度 | 项目 CLI wall 时间为 `164.008 ms`。相较 zip、tar.gz、tar.zst，耗时分别降低 `96.0%`、`98.4%`、`97.6%`。 |
| 归档体积 | Hig 归档大小为 `57,108,395 bytes`，比 zip 小 `15.7%`，比 tar.gz 小 `6.9%`，比 tar.zst 小 `12.0%`。 |
| 增量工作流 | 单文件改动和五文件改动归档分别完成于 `253.535 ms` 和 `96.243 ms`。 |
| 事件突发处理 | 1000 事件追赶耗时 `111.635 ms`，文件监听溢出次数为 `0`。 |
| 正确性 | 基准测试正确性摘要匹配：`true`。 |
| 桌面可用性 | v1.9.4 桌面包构建、校验和验证、lint、测试和 UI 溢出检查均通过。 |

## Hig 是做什么的

Hig 将一个项目打包为可恢复的加密归档，并重点优化重复项目快照场景。我们围绕这些工作流设计它：在高风险修改前保存项目状态、在不同机器间移动紧凑归档、保留快速本地恢复点，以及保存经过校验的发布产物。

本公开桌面发布仓库面向用户应用、文档和可下载安装包。

环境状态：`ENVIRONMENT_NOT_QUALIFIED`

由于该环境未标记为完全合格，以下数字应被视为透明的基准快照，而不是所有环境下的通用性能承诺。

## 结果解读

我们对这组数据的解读是：Hig 的优势主要体现在项目快照场景。当用户同时关注重复归档速度、输出体积和正确性校验时，Hig 在该测试负载下相较通用归档工具表现出更低耗时和更小输出。传统归档工具仍具有广泛兼容性，但在这个项目工作负载中 Hig 的效率优势更明显。
